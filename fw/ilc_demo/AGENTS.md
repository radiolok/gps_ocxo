# ИЛЦ1-8/7ЛВ — прошивка Arduino (PlatformIO)

Проект: тестовая прошивка для советского вакуумно-люминесцентного индикатора часового типа ИЛЦ1-8/7ЛВ (от авиационного хронометра ХАЭ-85М). Впоследствии будет интегрирован в проект DOROGO GNSS OCXO.

## Железо

| Компонент | Описание |
|-----------|----------|
| Индикатор | ИЛЦ1-8/7ЛВ (ВЛИ часового типа, 132 вывода, 62×76 мм) |
| Драйверы | 2× SN755870 (TQFP-100, 64-канальный high-voltage push-pull драйвер) |
| МК | Arduino Nano (ATmega328P, 16 МГц) |
| Питание | +5В (логика SN755870), +30В..+40В (VDDH высоковольтное) |
| Накал | Отдельный преобразователь, управляется пином EN |

### Подключение

SN755870 включены последовательно (daisy-chain SPI): MCU(MOSI) → DD2.SI → DD2.SO → DD1.SI. DIR=H (SI→SO) на обеих.

За 128 тактов SPI:
- Биты 0..63 уходят в DD1 (дальняя от МК)
- Биты 64..127 остаются в DD2 (ближняя к МК)

| ИЛЦ | Arduino Nano | Назначение |
|-----|-------------|------------|
| SI | MOSI – PB3 (D11) | Данные SPI |
| CLK | SCK – PB5 (D13) | Тактовый сигнал |
| CLR | PD2 (D2) | Сброс выходов SN755870 |
| OC2 | PD3 (D3) | ШИМ яркости (OC2B, Timer2) |
| OC1 | PD4 (D4) | Режим выходов: L=фиксированно для ШИМ |
| LAT | PD5 (D5) | Защёлка данных в выходной регистр |
| EN | PD6 (D6) | Вкл. преобразователь накала |

## Архитектура ПО

```
main.cpp              — точка входа, выбор активного демо (enum ActiveDemo)
├── demos/            — демо-приложения (4 шт.)
│   ├── demo_discovery — побитовый перебор сегментов для составления карты
│   ├── demo_seconds   — бегущая секундная стрелка по кольцу s1..s60
│   ├── demo_clock     — часы HH.MM на левом блоке, SS.cc на правом
│   └── demo_test_all  — циклический тест всех групп сегментов
├── display/          — уровень абстракции индикатора
│   ├── ilc1_8.h/.cpp  — высокоуровневое API (setDigit, setSecond, setLabel...)
│   ├── segment_map.h  — карта: логический сегмент → бит фреймбуфера (0..127)
│   └── font.h         — маски 7-сегментных цифр (a..g)
├── drivers/          — драйверы микросхем
│   └── sn755870.h/.cpp — управление цепочкой 2×SN755870, фреймбуфер 128 бит
└── hal/              — Hardware Abstraction Layer
    ├── pins.h         — конфигурация пинов и SPI
    └── pwm.h          — ШИМ яркости на Timer2 (D3, 62.5 кГц)
```

### Поток данных

```
demo → ilc1_8.setDigit(block, pos, value)
     → segment_map::digitSegment(block, pos, seg) → бит 0..127
     → SN755870Chain::setBit(idx, on) → buffer[16]
     → sendFrame() → SPI.transfer × 16 байт → latch()
     → сегменты индикатора
```

### Управление яркостью

- OC1 = L (фиксированно), OC2 = ШИМ (Fast PWM, Timer2, 62.5 кГц)
- H-фаза: выходы в режиме DATA (сегменты горят согласно фреймбуферу)
- L-фаза: выходы Hi-Z (все погашены)
- `setMaxBrightness(n)` задаёт верхний предел. При VDDH ≥ 35В рекомендуется ≤ 180 (70%)
- Полярность фреймбуфера: бит=1 → выход HIGH → сегмент горит (требует проверки)

## Сборка и прошивка

### Требования

- PlatformIO (VS Code или CLI)
- Плата Arduino Nano подключена по USB

### Команды

```bash
# Сборка
pio run -e nanoatmega328

# Прошивка
pio run -e nanoatmega328 -t upload

# Serial Monitor
pio device monitor -b 9600
```

### Выбор демо

В `main.cpp` изменить значение `gActiveDemo`:
- `DEMO_DISCOVERY` — обнаружение сегментов (основной режим для начала работы)
- `DEMO_SECONDS` — бегущая секундная стрелка
- `DEMO_CLOCK` — часы
- `DEMO_TEST_ALL` — полный тест всех групп

### Яркость

```cpp
gDisplay.setBrightness(128);  // 50%
// При VDDH ≥ 35В:
hal::pwm::setMaxBrightness(180);  // ~70% максимум
gDisplay.setBrightness(128);      // автоматически не превысит 180
```

## Процедура обнаружения сегментов

1. Собрать железо, подключить индикатор (ВНИМАНИЕ: сначала проверить работу SN755870 при 30В)
2. Установить `gActiveDemo = DEMO_DISCOVERY` в `main.cpp`
3. Прошить, открыть Serial Monitor (9600 бод)
4. Наблюдать: каждые 1.5 сек загорается один сегмент — записать соответствие «бит → что горит»
5. После прохода всех 128 битов (≈3 минуты) заполнить `segment_map.h` реальными значениями
6. Проверить полярность: действительно ли бит=1 зажигает сегмент, а не гасит

## Функциональность индикатора

| Группа | Кол-во | Обозначение |
|--------|--------|-------------|
| Секундное кольцо | 60 | s1..s60, по кругу |
| 7-сегм. блок 1 (левый) | 4 разряда + точка | 1a..8f, dot |
| 7-сегм. блок 2 (правый) | 4 разряда + точка | 1a..8f, dot2 |
| Плашка «ДАТА» | 1 | дата |
| Плашка «ТВ» | 1 | тв |
| Плашка «ПВ» | 1 | пв |
| Плашка «ВВОД» | 1 | ввод |
| Плашка «СЕК» | 1 | сек |
| Диск подсветки | 1 | диск |
| **Всего** | **124** | (128 бит − 4 свободных) |

## Известные проблемы

1. **segment_map.h — заглушка.** Все 60 секундных сегментов назначены как S1..S60 = биты 0..59 линейно, 7-сегментные блоки — биты 60..115 линейно. Реальное соответствие будет определено через `demo_discovery`.
2. **Полярность не проверена.** Код предполагает бит=1 → сегмент горит. При обратной логике нужна инверсия в `SN755870Chain::sendFrame()` или в карте сегментов.
3. **VDDH ниже 26В.** По словам Acho, выходы SN755870 могут не работать. Номинальное напряжение 35-40В. Требуется тестирование.
4. **Частота SPI 1 МГц.** При длинных дорожках может потребоваться снижение до 500 кГц (`SPI_CLOCK_DIV32`).

## Будущая интеграция (DOROGO GNSS OCXO)

- Код `display/` и `drivers/` оформляется как отдельная PlatformIO-библиотека
- Основной МК проекта будет вызывать API индикатора через I²C/UART или напрямую
- Плашки используются как индикаторы статуса: ДАТА, ТВ (точное время), ПВ (поясное время), ВВОД, СЕК
- Секундное кольцо — индикация секунд или статуса синхронизации GNSS
